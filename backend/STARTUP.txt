Employee Task Assignment backend startup and deployment (run from `employee-task-assignment-app/backend`)

Prerequisites (production host or container image)
1) Ruby 2.6+ and Bundler installed.
2) PostgreSQL database reachable from the app.
3) PostgreSQL client build tools available for the `pg` gem (`libpq` + `pg_config` on PATH).
4) Frontend static files available at `FRONTEND_ROOT` (default is repo parent directory `..`).

Production secret bootstrap (macOS Keychain)
1) Create local secret bundle file outside the repository (example: `~/.taskapp_prod_env`) with managed-central values:
- `STAGING_BASE_URL` and `PRODUCTION_BASE_URL` (public app/API base URLs)
- `STAGING_DATABASE_URL` and `PRODUCTION_DATABASE_URL` (runtime `app_rw` URLs)
- `STAGING_MIGRATION_DATABASE_URL` and `PRODUCTION_MIGRATION_DATABASE_URL` (migration/seed URLs; optional if same as runtime URL)
- Backward-compatible fallbacks are also supported: `BASE_URL` or `APP_BASE_URL`, `RUNTIME_DATABASE_URL`, `MIGRATION_DATABASE_URL`
- `DATABASE_ADMIN_URL`, `APP_DB_NAME`, `APP_RW_PASSWORD`, `APP_RO_PASSWORD`, `MIGRATION_ADMIN_PASSWORD` (for role provisioning)
- `MANAGER_EMAIL`, `MANAGER_PASSWORD`, `MANAGER_NAME`, `MANAGER_PHONE`
- Optional runtime app settings if needed: `RACK_ENV`, `APP_HOST`, `APP_PORT`, `PORT`, `FRONTEND_ROOT`, `CORS_ORIGINS`

2) Store secret bundle into Keychain service `taskapp-production`:
bash scripts/store_secrets_in_keychain.sh "${HOME}/.taskapp_prod_env"

3) Install gems:
bundle install --gemfile ./Gemfile

4) (Recommended, one-time per managed DB) provision least-privilege roles:
export DATABASE_ADMIN_URL="<postgres_admin_connection_url>"
export APP_DB_NAME="task_assignment"
export APP_RW_PASSWORD="<strong_password>"
export APP_RO_PASSWORD="<strong_password>"
export MIGRATION_ADMIN_PASSWORD="<strong_password>"
bash scripts/setup_production_roles.sh

5) Promote staging with schema/seed + full E2E + evidence capture:
bash scripts/promote_with_checks.sh staging
# Optional base URL override if not stored in Keychain:
# bash scripts/promote_with_checks.sh staging https://staging.example.com

6) After staging approval, promote production with the same checks:
bash scripts/promote_with_checks.sh production
# Optional base URL override if not stored in Keychain:
# bash scripts/promote_with_checks.sh production https://app.example.com

7) Launch finalization step 1 - set non-local HTTPS base URLs:
# Example (replace with your real DNS names):
export STAGING_BASE_URL="https://staging.example.com"
export PRODUCTION_BASE_URL="https://app.example.com"
bash scripts/store_secrets_in_keychain.sh "${HOME}/.taskapp_prod_env"

8) Launch finalization step 2 - run backend on host/container behind HTTPS:
# Provide real certificate/key in production (recommended):
export HTTPS_CERT_FILE="/path/to/fullchain.pem"
export HTTPS_KEY_FILE="/path/to/privkey.pem"
APP_HOST=0.0.0.0 APP_PORT=8443 RACK_ENV=production \
DATABASE_URL="<managed_runtime_database_url>" \
bash scripts/start_web_https.sh
# Local smoke path (self-signed cert auto-generated):
# APP_HOST=0.0.0.0 APP_PORT=8443 RACK_ENV=production DATABASE_URL="<managed_runtime_database_url>" bash scripts/start_web_https.sh
9) Evidence output is written to `backend/verification_evidence/`:
- `<env>_verification_<timestamp>.json` from `run_rollout_verification.sh`
- `<env>_promotion_<timestamp>.json` from `promote_with_checks.sh`

10) Manual web process start (HTTP, if needed outside scripted rollout):
# Runtime DB credentials should be least-privilege role (`app_rw`) and managed URL with TLS.
export PORT=${PORT:-4567}
./scripts/start_web.sh

Validated Neon-backed execution sequence (local app + managed DB)
1) Ensure Neon URLs are in `~/.taskapp_prod_env`:
- `DATABASE_ADMIN_URL`, `RUNTIME_DATABASE_URL`, `MIGRATION_DATABASE_URL` should point to `*.neon.tech` with `sslmode=require`.

2) Reload Keychain from env bundle:
bash scripts/store_secrets_in_keychain.sh "${HOME}/.taskapp_prod_env"

3) Confirm runtime host is managed (non-local):
bash scripts/load_secrets_from_keychain.sh -- ruby -ruri -e 'u=ENV["RUNTIME_DATABASE_URL"]||ENV["DATABASE_URL"]||""; puts URI(u).host'

4) Apply schema + seed manager with migration URL:
bash scripts/load_secrets_from_keychain.sh -- bash -lc 'DATABASE_URL="$MIGRATION_DATABASE_URL" bundle exec ruby scripts/setup_db.rb'

5) Start backend on local port with Neon runtime DB:
lsof -ti tcp:4567 | xargs kill 2>/dev/null || true
bash scripts/load_secrets_from_keychain.sh -- bash -lc 'nohup env DATABASE_URL="$RUNTIME_DATABASE_URL" APP_HOST=127.0.0.1 APP_PORT=4567 PORT=4567 FRONTEND_ROOT=.. RACK_ENV=production scripts/start_web.sh >/tmp/taskapp_backend_neon.log 2>&1 &'

6) Run full E2E verifier and capture evidence:
bash scripts/run_rollout_verification.sh staging http://127.0.0.1:4567

Verification checklist (expected HTTP status in parentheses)
- Capture and retain verification evidence (HTTP statuses and generated `employee_id`/`task_id`) with deployment records.
1) Health check:
- `GET /api/health` (200)

2) Website root check:
- `GET /` (200) and response contains `Employee Task Assignment`

3) Manager login:
- `POST /api/auth/login` with manager credentials (200), capture `manager_token`

4) Create employee:
- `POST /api/employees` with manager token (200), capture `employee_id`

5) Employee login:
- `POST /api/auth/login` with new employee credentials (200), capture `employee_token`

6) Assign task:
- `POST /api/tasks` with manager token and `assigneeId=employee_id` (200), capture `task_id`

7) Send reminder:
- `POST /api/tasks/:task_id/reminder` with manager token (200)

8) Employee completes task:
- `POST /api/tasks/:task_id/complete` with employee token (200), response task `status=Completed`

9) Manager workspace verification:
- `GET /api/workspace` with manager token (200), task with `id=task_id` has `status=Completed`

Operational notes
- `scripts/promote_with_checks.sh` and `scripts/run_rollout_verification.sh` reject localhost DB URLs to enforce managed central database usage.
- All rollout commands auto-load secrets from Keychain via `scripts/load_secrets_from_keychain.sh`.
- Frontend uses same-origin API requests at `/api` by default.
- Optional frontend API override remains available via `window.TASK_APP_API_BASE_URL` in `index.html`.
- For phased enterprise rollout, monitoring, rollback, and access governance, follow `ROLLOUT_RUNBOOK.txt`.
